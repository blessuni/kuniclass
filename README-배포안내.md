# 진주반 우리 모둠 마음보석 — Netlify 배포용

## 먼저 알아둘 점

이 폴더는 화면 파일뿐 아니라 공유 저장을 위한 Netlify 서버 함수를 포함합니다.
**Netlify Drop에 dist 폴더만 끌어 놓으면 화면만 배포되고, 태블릿 간 공유는 작동하지 않습니다.**
아래 CLI 방법 또는 Git 연결 방법으로 배포하세요. 별도의 Firebase/Supabase 계정이나 데이터베이스 API 키는 필요하지 않습니다.
Netlify 계정 로그인 및 해당 계정의 사이트 생성/선택은 선생님이 진행합니다.

## 가장 빠른 배포 — 완성 파일을 그대로 올리기

1. Node.js 22 이상을 설치하세요.
2. 이 폴더에서 터미널을 열고 아래를 실행하세요.

```sh
npm ci
npx netlify login
npm run deploy:ready
```

Netlify가 사이트를 물으면 새 사이트를 만들거나 사용할 사이트를 선택하세요.
완성된 dist 화면과 deploy-functions 서버 함수가 함께 올라갑니다.
Windows에서는 deploy.cmd, macOS/Linux에서는 bash deploy.sh로 같은 과정을 실행할 수 있습니다.
인증 토큰이나 비밀번호를 코드 파일에 넣지 마세요.

## Git 연결로 배포

1. 이 폴더 전체를 Git 저장소에 올립니다. node_modules와 .netlify는 올리지 않습니다.
2. Netlify에서 저장소를 연결합니다.
3. 설정은 netlify.toml에서 자동으로 읽습니다.
   - 빌드: npm run build
   - 화면 폴더: dist
   - 서버 함수: netlify/functions
4. 배포를 시작합니다. Netlify가 공유 저장소 연결 정보를 서버에 자동으로 제공합니다.

## 태블릿과 교사 화면 사용

- 모든 태블릿에서 **같은 Netlify 사이트 주소**를 엽니다.
- 각 태블릿에서 자기 모둠을 한 번 고릅니다. 새로고침 시 해당 활동이 이어집니다.
- 참관교사용은 보라색이며 존중·경청·공감·협동 중 2개를 고릅니다.
- 오른쪽 위 작은 집을 누르면 확인 후 홈으로 이동합니다. 모둠별 선택·역할·완료 기록은 지워지지 않습니다.
- 교사 기기에서 ⚙️를 약 2초 누르고 전체 진행상황을 누릅니다.
- 위쪽 진주반 4모둠과 아래쪽 참관 선생님을 따로 표시합니다.
- 참관교사 여러 기기는 체험 1, 체험 2처럼 각각 표시합니다. 같은 유아 모둠에 여러 기기가 있으면 각 태블릿의 단계도 표시합니다.
- 전체 진행상황은 약 4초마다 서버 기록을 다시 확인합니다. 네트워크 속도에 따라 반영 시간이 달라질 수 있습니다.
- 인터넷이 끊겨도 선택과 활동 기록은 해당 태블릿에 남습니다. 연결이 돌아오면 또는 10초 간격으로 서버 저장을 재시도합니다. 연결이 끊긴 동안 다른 기기에 새 상태가 전달되지는 않습니다.
- 교사용 설정에서 공유 연결 상태를 확인할 수 있습니다.
- Canva에는 앱이 사진을 자동 업로드하지 않습니다. 안내에 따라 올림이가 자기 모둠 색 칸에 직접 사진을 올립니다. 업로드 뒤 브라우저 뒤로 돌아와 사진 올렸어요를 누릅니다.
- Canva 이동: https://canva.link/lg44g9coxwzxamt

## 저장 방식

- localStorage: 해당 기기의 모둠 설정, 모둠별 이어하기 기록, 익명 기기 번호, 인터넷 끊김 대비 기록.
- Netlify Function /api/progress: 기록 검증과 공유 저장/조회.
- Netlify Blobs: 모든 기기가 함께 읽는 site-wide 저장소 jinju-maeum-progress-v1. strong consistency를 사용합니다.
- 각 기기·모둠별 독립 기록을 저장합니다. 유아는 child, 참관교사는 observer로 나눕니다.
- 공유하는 정보는 모둠, 보석 이름, 완료 여부, 역할 화면 선택, 활동 단계와 기록 시각입니다. 유아 이름이나 촬영 사진은 저장하지 않습니다.
- 사이트를 새로 배포해도 같은 Netlify 사이트의 공유 기록은 유지됩니다. 다른 Netlify 사이트를 만들면 다른 저장소를 사용합니다.
- 이 태블릿 기록 초기화는 현재 모둠의 이 기기 기록만 처음부터 다시 시작합니다. 다른 기기의 기록을 지우지 않습니다.
- 교사용 설정은 길게 누르기로 숨겨 둔 화면이며 별도의 교사 계정 로그인 기능은 없습니다.

## 파일 구성

- dist/: 이미 빌드된 웹 화면, 글꼴, 그림자료
- deploy-functions/: 이미 묶은 Netlify 서버 함수
- netlify/functions/: 서버 함수 원본
- server/: 공유 기록 검증·단계 처리
- src/: 전체 화면 원본
- public/: 글꼴·그림·공식 Canva 로고
- netlify.toml: 빌드, API 경로, 함수 설정
- package-lock.json: 동일한 버전 설치용
- tests/: 공유 저장, 데이터 분리, 초기화, 잘못된 요청, 이전 기록 덮어쓰기, 오류 처리 테스트

## 수정 후 다시 배포

```sh
npm ci
npm test
npm run build
npm run bundle-functions
npm run deploy:ready
```

또는 npm run deploy를 사용하면 빌드와 소스 함수 배포를 함께 진행합니다.

## 확인한 내용과 마지막 현장 확인

- 기존 화면에서 2개 선택 제한·선택 취소·역할·촬영 완료·자리 복귀·사진 확인·추가 3/4번째 선택·홈 복귀·새로고침 유지 동작을 브라우저로 확인했습니다.
- Netlify CLI의 실제 로컬 함수 실행과 로컬 Blobs 저장소에서 서로 다른 기기 기록을 저장하고 함께 조회하는 테스트가 통과했습니다.
- 자동 테스트 17개가 통과했습니다. 유아/참관 기록 분리, 기기별 기록 유지 및 초기화, 잘못된 요청 차단, 늦게 도착한 이전 기록 무시, 서버 오류 표시를 확인했습니다.
- 이 파일은 아직 선생님의 Netlify 계정에 배포되지 않았습니다. 실제 운영 URL, 원격 Netlify Blobs 연결, 현장 태블릿/네트워크, Canva 편집 권한은 배포 후 확인해야 합니다.
- 배포 뒤 태블릿 A에서 보석을 골라 역할 화면까지 이동하고, 기기 B에서 전체 진행상황을 열어 A의 단계가 나타나는지 확인하세요. A를 새로고침해도 선택이 이어지는지 확인하세요.

## 촬영 흐름 수정
첫 보석 완료 → 하나 완성 화면과 다음 보석 안내 → 두 보석 촬영 완료 → 두 보석 완료 확인 → 자리로 돌아가기 → 모였어요 → 사진 함께 확인 → 자기 모둠 색 Canva 안내 → 사진 올리기 → 사진 올렸어요 → 완료. 한 개 완료 상태에서는 자리 복귀·사진 확인·Canva 단계로 갈 수 없습니다. 이전 버전의 한 개 완료 업로드 화면도 다시 표현 화면으로 복원합니다. 같은 조건을 서버 기록 검증에도 적용했습니다. 추가 보석은 해당 촬영을 마친 뒤 같은 확인 흐름을 거칩니다.

## 다섯 모둠 화면 재점검 결과
다람쥐·낙엽·잠자리·바람·참관교사용의 실제 React 화면 컴포넌트를 DOM 시험 환경에서 렌더링해 버튼을 눌러 검사함. 첫 완료 직후 자리 복귀·사진 확인·Canva 요소 미표시, 1/2 localStorage 저장, 앱 제거 후 재실행의 복원, 홈 확인창과 모둠 재진입의 복원, 두 번째 완료의 두 체크, 자리 복귀→모였어요→사진 확인→자기 색 업로드 안내 순서를 모두 확인함. 새로고침 검사는 앱을 제거했다 다시 실행하여 저장 복원 코드를 검사하는 방식임. 운영 브라우저의 시각적 배치 검사와 Canva 외부 페이지 접속 검사는 별도임. 화면 검사 5개와 활동 조건·공유 저장 검사 12개, 총 17개 통과함.
